# Design

This module lets a municipality decide who may take part in Stadtstack civic
participation, and lets those people vote in advisory polls without revealing
how they voted. It has two parts:

- an **eligibility issuer** that confirms eligibility under one municipality's
  published policy and emits the Stadtstack wire artifacts; and
- an **anonymous advisory participation lane**: identity commitments, a frozen
  anchor per poll, Noir membership proofs with scoped nullifiers, and a
  reproducible tally.

Nothing here creates binding decisions. Receipts carry
`authorityBinding: "civic_eligibility_only"` exactly as Stadtstack requires;
poll results are `advisory_non_binding` and project to Stadtstack's
`participation_result_v1` with `authorityBinding: "none"`.

This document is normative for the code in this repository. When code and
this document disagree, one of them is a bug.

## Non-goals

- Binding elections or referendums. These need a separate legal basis and a
  separate design.
- Identity proofing beyond what an adapter states. Each adapter documents
  exactly what it checks.
- Storing personal data. No record in this module contains a name, address,
  birth date or document number.
- Copying code from differently licensed products. Interfaces of other
  systems (for example a public contract ABI) are reimplemented from their
  public specification.

## Conventions

- Timestamps are integer Unix seconds.
- Nostr keys, event ids and SHA-256 digests are lowercase 64-character hex
  without prefix. EVM values (addresses, `bytes32`, field elements) are
  `0x`-prefixed lowercase hex; field elements are 32-byte big-endian.
- **Canonical JSON** is byte-identical to Stadtstack's: object keys sorted
  recursively, values serialised with `JSON.stringify`, only safe integers,
  strings, booleans, `null`, arrays and plain objects. `digest(value)` is the
  lowercase SHA-256 hex of the UTF-8 canonical JSON.
- Untrusted JSON is read through a bounded snapshot (size, depth and node
  limits) and checked against an exact key set. Unknown keys are rejected.

## Identifiers

| Name | Format |
|---|---|
| `municipalityId` | Stadtstack registry unit id: `^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$` |
| `ags` | 8-digit Amtlicher Gemeindeschlüssel of that unit |
| `policyVersion` | `^[a-z0-9][a-z0-9._-]{2,99}$` |
| `topicId` | `urn:stadtstack:topic:municipality:<municipalityId>:<slug>` |
| `electionSlug` | same pattern as `municipalityId` |
| `electionId` | `0x` + `digest({schemaVersion: "advisory_election_id_v1", municipalityId, policyVersion, electionSlug})` |

Eligibility is keyed by `municipalityId` and `ags`, never by postal code.
Postal areas cross municipal boundaries.

## Hashing

All circuit-relevant hashes use the BN254 scalar field
`r = 21888242871839275222246405745257275088548364400416034343698204186575808495617`
and one domain-separated compression function:

```
h(a, b, d) = poseidon2_permutation([a, b, d, 0])[0]
```

Noir: `std::hash::poseidon2_permutation(state, 4)`. TypeScript:
`permute([a, b, d, 0n])[0]` from `@zkpassport/poseidon2@0.6.2`. A parity
fixture generated by Noir pins the equality.

| Domain | `d` | Value |
|---|---|---|
| Identity | 1 | `identityCommitment = h(secret, 0, 1)`, `secret ∈ [1, r-1]` |
| Merkle node | 2 | `node = h(left, right, 2)` |
| Nullifier | 3 | `nullifier = h(secret, scope, 3)` |
| Scope | 4 | `scope = h(hi128(electionId), lo128(electionId), 4)` |
| Signal | 5 | `signalHash = h(choiceIndex, scope, 5)`, `choiceIndex ∈ [0, 255]` |

The Merkle tree has fixed depth **16** (65,536 leaves). Empty leaves are `0`.
Bit `i` of the leaf index (least significant first) is `indices[i]`; `0`
means the current node is the left child.

## Circuit `circuits/membership_vote`

```
fn main(
    secret: Field, path: [Field; 16], indices: [Field; 16],
    root: pub Field, nullifier: pub Field, scope: pub Field, signal_hash: pub Field,
)
```

Constraints: `secret != 0`; `scope != 0`; every index is boolean; the root
recomputed from `identityCommitment` equals `root`;
`nullifier == h(secret, scope, 3)`; `signal_hash` is bound as a public input.
Public input order: `root, nullifier, scope, signal_hash`.

Proofs are UltraHonk with the Keccak oracle hash and zero knowledge, so that
the generated Solidity verifier and `@aztec/bb.js` verify the same proof bytes.

## Election registry `contracts/src/ElectionRegistry.sol`

- Constructor takes `admin`, `operator` and the verifier explicitly. The
  deployer gets no role.
- `openElection(electionId, municipalityId, anchorRoot, treeDepth, metadataHash, scope, opensAt, closesAt)`
  by `ELECTION_OPERATOR_ROLE`; requires `treeDepth == 16`, non-zero root,
  `0 < scope < r`, `opensAt < closesAt`, `closesAt > block.timestamp`, and a
  fresh `electionId`. The anchor cannot change afterwards.
- `closeElection(electionId, tallyHash, acceptedBallots)` by the operator,
  only after `closesAt`.
- `getElection(electionId)` returns the full record so clients can check what
  a server tells them.
- `verifyBallot(electionId, proof, nullifier, signalHash)` checks a ballot
  against the on-chain anchor and scope, so anyone can audit a published
  tally.

## Advisory participation lane `src/vote`

### Client key material

All client secrets come from the WebAuthn PRF extension of a passkey,
evaluated with `userVerification: "required"`. There is no fallback storage:
a device without PRF fails with `prf_unavailable`. For a purpose `p` in one
municipality:

- PRF salt: `sha256("stadtstack-participation/" + p + "/v1/" + municipalityId)`;
- expansion: `HKDF-SHA256(ikm = prfOutput, salt = "stadtstack-participation",
  info = p + "/v1/" + municipalityId)`.

| Purpose `p` | PRF slot | Result |
|---|---|---|
| `person-secret` | participant `first` | voting secret: 64 bytes mod `r`, zero rejected |
| `nostr-subject` | participant `second` | Nostr secret key: 48 bytes mod `(n − 1)` plus 1, with `n` the secp256k1 order |
| `attestor-key` | attestor `first` | Ed25519 secret key: 32 bytes |

A participant gets both values from one assertion. The Nostr subject key is
the public identity towards the issuer (NIP-98) and in Stadtstack receipts;
different salts keep it cryptographically independent of the voting secret,
and a person has unrelated keys in different municipalities. The passkey is
bound to the exact host serving the client (see "Clients and hosting"); no
helper accepts an `rpId`.

### Enrollment (issuer side)

A holder enrolls an identity commitment with a NIP-98-signed request from
their Nostr key and adapter evidence. One active commitment per
`(municipalityId, subjectPubkey)`. Replacing it is refused while an open
poll's anchor contains the current commitment.

### Anchor

```
{ schemaVersion: "advisory_election_anchor_v1", municipalityId, policyVersion,
  electionId, treeDepth: 16, leaves: [0x…], root: 0x…, anchoredAt }
```

`leaves` are the commitments of enrollments whose eligibility re-check is
active at `anchoredAt`, unique, non-zero and **sorted ascending as numbers**,
so leaf positions reveal nothing about enrollment or attestation order. Once
an election is opened with the root, the stored anchor is immutable.

### Election metadata

```
{ schemaVersion: "advisory_election_metadata_v1", municipalityId, policyVersion,
  electionId, electionSlug, title, question, choices: [{ index, label }],
  opensAt, closesAt, legalEffect: "advisory_non_binding",
  participationContract: { id, version } }
```

`metadataHash = 0x + digest(metadata)`.

### Client checks

Before proving, a client reads `getElection(electionId)` from the chain and
refuses to continue unless the anchor root, metadata hash, scope and window
match what the server returned, and unless `scope` equals the scope derived
from `electionId`. Ballots are sent with `credentials: "omit"`,
`cache: "no-store"` and `redirect: "error"`.

### Ballot intake (normative order)

1. Body at most 32 KiB, JSON, exact shape
   `{ schemaVersion: "advisory_ballot_v1", electionId, choiceIndex, nullifier, signalHash, proof }`.
2. Election known, open, and `now ∈ [opensAt, closesAt)`.
3. `signalHash == h(choiceIndex, scope, 5)`, `choiceIndex` is a valid choice,
   `0 < nullifier < r`.
4. Per-client rate limit (keys held in memory only), plus a global cap on
   concurrent proof verifications.
5. Reject a nullifier that is already stored.
6. Verify the proof with public inputs `[anchorRoot, nullifier, scope, signalHash]`.
7. Insert. A `UNIQUE(election_id, nullifier)` constraint decides races.

Stored ballots carry no timestamps, sessions or client identifiers. The reply
is `{ ok: true }` or `{ ok: false, code }`.

### Tally

```
{ schemaVersion: "advisory_tally_v1", municipalityId, policyVersion, electionId,
  anchorRoot, metadataHash, scope, window: { opensAt, closesAt },
  choices: [{ index, label, count }], totalAccepted,
  ballots: [{ nullifier, choiceIndex, signalHash, proof }],
  verifier: { circuitSha256, vkHash } }
```

`ballots` are sorted ascending by nullifier. The window comes from the chain;
the tally contains no wall-clock time, so anyone can rebuild it byte for byte.
`tallyHash = 0x + digest(tally)` is what `closeElection` records. The result
projects to Stadtstack's `participation_result_v1`.

## Eligibility issuer `src/issuer`

### Policy `municipal_eligibility_issuer_policy_v1`

```
{ schemaVersion, municipalityId, ags, policyVersion,
  registry: { snapshotId, digest: "sha256:<hex>" } | null,
  issuer, issuerKeyId, issuerPublicKey, publicBaseUrl,
  statusBaseUrl, acceptanceBaseUrl,
  receiptTtlSeconds, statusMaxAgeSeconds, maxEventClockSkewSeconds,
  allowedAgentPubkeys,
  basis: { residence: "main_residence" | "main_or_secondary_residence",
           minimumAgeYears: integer | null,
           nationality: "any" | "eu_citizen" | "german_citizen",
           localityScope: [registry locality id] | null },
  adapter: <adapter config> }
```

- `publicBaseUrl` is HTTPS without path, query, fragment or trailing slash.
  `statusBaseUrl` must equal `publicBaseUrl + "/v1/eligibility/status"` and
  `acceptanceBaseUrl` must equal `publicBaseUrl + "/v1/adoptions"`.
- Limits match Stadtstack: receipt TTL 60–3600 s, status max age 1–300 s,
  clock skew 0–300 s.
- The policy is public. The Ed25519 signing key is loaded at runtime from a
  file or environment reference and never appears in the policy or database.
  Policy validation rejects an issuer key that equals an attestor key.
- `toStadtstackPolicy()` exports exactly Stadtstack's
  `CitizenAdoptionEvidencePolicy` for the deployment that verifies receipts.

### Wire artifacts

The issuer emits exactly the shapes Stadtstack verifies in
`src/citizen-adoption-evidence.ts` of the Stadtstack repository:

- `municipal_civic_eligibility_receipt_v1` with `eligibilityClass:
  "municipal_civic_participation"`, `subjectPubkey` = the requesting Nostr
  key, `expiresAt = issuedAt + receiptTtlSeconds`, `issuedAt` not earlier than
  the suggestion event, Ed25519 proof over
  `{ domain: "municipal-civic-eligibility-receipt/v1", schemaVersion, receiptId, payloadChecksum, statusRef }`;
- `municipal_civic_eligibility_status_v1`, freshly re-checked through the
  adapter, echoing `x-stadtstack-status-nonce`, audience
  `stadtstack-case-steward-admission`;
- `citizen_topic_suggestion_adoption_acceptance_receipt_v1`, served from the
  adoption ledger.

An interoperability test runs Stadtstack's own verifier (vendored, pinned)
against this issuer.

### HTTP endpoints

| Method and path | Auth | Purpose |
|---|---|---|
| `POST /v1/eligibility/receipts` | NIP-98 (subject key) | Issue a receipt for one suggestion |
| `GET /v1/eligibility/status/<payloadChecksum>` | nonce header | Signed fresh status |
| `POST /v1/adoptions` | adoption event signature | Record acceptance |
| `GET /v1/adoptions/<adoptionEventId>` | none | Acceptance receipt |
| `POST /v1/attestations` | attestor signature | Record an in-person attestation |
| `POST /v1/attestation-revocations` | attestor signature | Record a revocation |
| `POST /v1/identity-commitments` | NIP-98 (subject key) | Enroll a voting commitment |
| `GET /v1/policy` | none | Public issuer policy |
| `GET /v1/client-config` | none | What the web clients need: municipality, basis, adapter, chain |
| `GET /v1/eligibility/me` | NIP-98 (subject key) | The caller's own eligibility and enrollment |
| `POST /v1/eudi/requests` | NIP-98 (subject key) | Start an EUDI wallet presentation (`eudi_pid_v1` only) |
| `GET /v1/eudi/requests/<transactionId>` | NIP-98 (same subject) | Presentation state |
| `GET /v1/elections` | none | Open and closed polls, newest first; drafts are not listed |
| `GET /v1/elections/<electionId>` | none | Election mirror and metadata |
| `GET /v1/elections/<electionId>/anchor` | none | Anchor artifact |
| `POST /v1/elections/<electionId>/ballots` | none (ZK proof) | Ballot intake |
| `GET /v1/elections/<electionId>/tally` | none | Tally after close |

Every response is `application/json` with `cache-control: no-store` and sets
no cookies. Errors are `{ "error": "<code>" }`.

NIP-98 requests use a kind-27235 event in `Authorization: Nostr <base64>`
with tags `u` (exact URL under `publicBaseUrl`), `method` and `payload`
(SHA-256 of the body), `created_at` within the configured skew, and a
single-use event id.

`GET` requests with NIP-98 carry only the `u` and `method` tags.

Response shapes of the client endpoints:

- `GET /v1/client-config`:
  `{ schemaVersion: "participation_client_config_v1", municipalityId, ags,
  policyVersion, displayName, operator: { name, isMunicipality },
  publicBaseUrl, adapterKind, basis,
  attestors: [{ attestorId, publicKey }] | null, chain: { chainId,
  registryAddress, rpcUrl } | null }`. `attestors` is non-null only for
  `in_person_attestors_v1`; the keys are already public in the policy.
  Both clients show `operator`: an independent operator always states that the
  service is not offered by the municipality's administration.
  `chain` is null until the operator configures a deployed registry.
- `GET /v1/elections`: `{ elections: [{ electionId, state, opensAt, closesAt,
  anchorRoot, scope, metadataHash, metadata }] }`.
- `GET /v1/eligibility/me`: `{ subjectPubkey, eligibility: { state: "active",
  effectiveAt, validUntil } | { state: "inactive", reason }, enrollment:
  { identityCommitment, enrolledAt } | null }`. With an active enrollment the
  adapter re-checks its evidence; without one, `preview` answers if the
  adapter has it, otherwise the reason is `evidence_required`.

### Adapter seam

Adapters live in `src/adapters` and implement `EligibilityAdapter` from
`src/shared/seams.ts`. `check` evaluates evidence for a request; `recheck`
re-evaluates a stored issuer-private `evidenceRef` for status responses and
anchors; the optional `preview` evaluates a subject without request evidence.
Adapters never appear in receipts.

A policy names exactly one adapter. Evidence from two adapters cannot be
matched to one person, so mixing them would let a person enroll once per
adapter.

#### `in_person_attestors_v1`

Config: `attestors [{ attestorId, publicKey, ownSubjectPubkeys, validFrom, validUntil }]`,
`requiredAttestations` (K ≥ 2), `attestationWindowSeconds`,
`validitySeconds`, `revocationThreshold` (R ≥ 1).

An attestation is an Ed25519 signature by a listed attestor over
`{ domain: "in-person-residency-attestation/v1", core }` with
`core = { schemaVersion: "in_person_residency_attestation_v1", municipalityId, policyVersion, subjectPubkey, attestorId, attestedAt, basis, documentKinds }`.
`basis` must equal the policy basis. `documentKinds` names document types
seen, never document data.

Rules, for a subject at time `t`. Records with timestamps `≤ t` are replayed
in ascending time order; records with equal timestamps are processed together.

1. An attestation counts only if it falls inside the attestor's
   `[validFrom, validUntil)` interval and the subject is not one of the
   attestor's own keys (no self-attestation). A signature that was valid when
   made stays valid after the attestor's authorization ends.
2. Only each attestor's latest counting attestation is considered.
3. After each time group, take the K most recent attestations of distinct
   attestors. They form a **cohort** if
   `newest − oldest ≤ attestationWindowSeconds`; then
   `effectiveAt = newest` and `validUntil = oldest + validitySeconds`.
4. An established cohort is frozen until all K candidates are strictly newer
   than its `effectiveAt`. An attestation that belonged to one cohort can
   therefore never help extend it: renewal needs K attestations made after
   the current cohort became effective. The next cohort replaces the old
   validity interval; it never adds to it.
5. Each attestor's latest revocation counts. The current cohort is revoked
   when at least R distinct attestors revoked at or after its `effectiveAt`.
   Revocation erases neither attestations nor the cohort boundary; only a new
   cohort whose `effectiveAt` is later than enough revocations restores
   eligibility.

#### `roebel_citizen_nft_v1`

Bridges Röbel's on-chain citizen status without using Röbel code. Config:
`chainId`, `contractAddress`, `expectedCodeHash`, `blockTag`,
`walletProofMaxAgeSeconds`; the RPC endpoint is runtime configuration.
Evidence is an EIP-191 signature by the citizen's wallet (EOA, ERC-1271 or
ERC-6492) over a fixed text that binds municipality, policy version, subject
key, purpose, request id and time. The adapter checks the contract's code
hash and calls `isActive(wallet)` at `blockTag`. `evidenceRef` is the wallet
address, kept private by the issuer.

#### `eudi_pid_v1`

Eligibility from an EU Digital Identity Wallet presentation (OpenID4VP) of
the person identification data (PID); test-only for now. Design and limits:
[ADR 0006](adr/0006-eudi-pid-adapter.md).

The adapter requests exactly `family_name`, `given_name`, `birthdate`,
`address.postal_code` and `address.locality`. The PID carries no municipality
key, so the policy lists the accepted `(postal code, locality)` pairs. Age is
computed from the birth date.

Wallets present one-time credentials with a fresh holder key each time, so a
holder key cannot identify a person across presentations. `evidenceRef` is
therefore a keyed hash (HMAC-SHA256 under an operator-held key separate from the
issuer key) of the normalized names and birth date. Names, birth date and
address are used in memory and never stored, logged or returned.

## Clients and hosting

One host serves the API and both web clients, for example
`mitmachen.stadtstack.eu`. Passkeys are bound to that exact host: a client
never sets `rpId`, and the host is never registered for a parent domain,
because any origin allowed to use the same passkey and the public PRF salt
could derive the voting secret. No other application shares the host.

- `/` is the participant client: create the passkey, show the subject code,
  check eligibility, enroll, see polls, prove and send a ballot, see results.
- `/pruefung` is the attestor client: derive the attestor key, show its public
  key for the policy, scan a subject code, sign attestations and revocations.
- City-facing text is German.

The subject code that an attestor scans is the text
`stadtstack-participation/subject/v1/<municipalityId>/<subjectPubkey>`. Both
devices show the fingerprint `xxxx xxxx … xxxx xxxx` (first and last eight hex
digits) so the attestor can compare it with the person's screen.

HTML and assets are served with `Content-Security-Policy` limited to the own
origin plus the configured RPC origin (`script-src 'self' 'wasm-unsafe-eval'`,
`worker-src 'self' blob:`), `Cross-Origin-Opener-Policy: same-origin`,
`Cross-Origin-Embedder-Policy: require-corp`, `Referrer-Policy: no-referrer`,
`X-Content-Type-Options: nosniff` and a `Permissions-Policy` that allows only
camera and passkeys for the own origin.

The clients fetch API paths relative to their own origin and sign NIP-98 for
`publicBaseUrl` plus the path. Only passkey credential ids are kept in browser
storage. Proofs are computed in a module worker from same-origin assets: the
Noir and Barretenberg WASM, the circuit, and the BN254 CRS prefix the circuit
needs (`web/public/assets/crs`, 2^11 + 1 points; `provenance.json` pins source
and hashes). Changing the circuit size requires replacing that prefix.

## Storage

`node:sqlite`, one database. Each module creates its own tables through an
idempotent `migrate(db)`. Uniqueness that matters for safety is enforced by
the database:

- one ballot per `(election_id, nullifier)`, stored only while the election is
  open and untallied; storing a tally requires that it counts exactly the
  stored ballots and closes intake, so an acknowledged ballot is always counted;
- one active enrollment per `(municipality_id, subject_pubkey)` and per
  `(municipality_id, evidence_ref)`. A new subject key presenting the same
  evidence (e.g. after a lost passkey) supersedes the old enrollment unless an
  open poll's anchor contains its commitment;
- one subject per `(participant_suggestion_id, evidence_ref)`, so one person
  adopts a suggestion only once;
- one acceptance per `(municipality_id, participant_suggestion_id, adopter_pubkey)`;
- single-use NIP-98 event ids.

## Operations

`npm run operator -- <command>` (`src/cli/operator.ts`) prepares everything an
operator signs elsewhere; it never holds a chain key.

- `issuer-key`: write a new Ed25519 issuer key as PKCS#8 PEM (mode 0600) and
  print its public key.
- `policy`: build and validate a policy from a pinned Stadtstack registry
  snapshot (unit id → AGS and snapshot digest) and explicit basis, adapter and
  URL options; print the Stadtstack verifier policy.
- `poll-draft`: compute the election id and metadata hash, build the anchor
  from current eligibility, store the draft, and write a Safe Transaction
  Builder batch plus the equivalent `cast send` command for `openElection`.
- `poll-confirm-open` / `poll-confirm-close`: read the registry and record the
  on-chain state in the mirror.
- `poll-tally`: after `closesAt`, build and store the tally and write the
  batch for `closeElection`.
- `poll-result`: project a closed poll to `participation_result_v1` with
  caller-supplied review context.

The registry's admin and operator are a Safe. Staging uses Gnosis Chiado.
